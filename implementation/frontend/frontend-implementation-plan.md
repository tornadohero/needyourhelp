# Frontend Implementation Plan — 前端实施计划（T027）

本计划只做**契约对齐与开发准备**：建立前端可依赖的 API 地图、页面地图与任务分解。
**不在本轮创建页面、不改后端、不改数据库。**

## 2. 总体策略

1. **契约先行**：前端只依赖 `packages/api-contracts`（`@mentor/api-contracts`）导出的类型与 `ENDPOINTS`，
   不在前端复制接口定义；新增后端能力必须先补契约再补前端。
2. **先管理台后小程序**：管理台是"让平台能被运营"的最短路径，且不受微信审核/真机限制；
   小程序依赖登录与支付真机能力，放在管理台之后（但 G1 需先决策）。
3. **能力缺口先决策再动工**：G1/G3/G4 属阻塞项，应先以任务形式确认是否新增后端接口，
   前端不绕过（例如：不得用微信 mock 登录充当生产管理台登录）。
4. **状态机不得前端化**：订单、商家、验证、合规、审核的状态一律由服务端命令端点驱动；
   前端只展示与刷新，遇 `ORDER_INVALID_STATE`/`PROVIDER_NOT_APPROVED` 等 409 时提示并刷新。
5. **金额服务端为准**：前端不计算、不传金额；只格式化展示 `amountMinor`（分 → 元）。
6. **错误码驱动 UI**：按 `error.code` 分支（401 重登、403 无权限、404 不存在、409 状态冲突、429 退避），
   不解析 `message` 做逻辑判断。

## 3. 共享前端基建（两端通用）

| 组件 | 内容 |
|---|---|
| API client | 单一 `fetch` 封装：baseURL + `/api/v1`、注入 Bearer、自动 refresh（401 → `/auth/refresh` → 重放一次）、透传 `x-request-id`、解包 `{data}`、抛 `{code,status}` |
| 类型来源 | 直接 `import type { … } from '@mentor/api-contracts'`；`ENDPOINTS` 常量拼路径 |
| 错误处理 | 错误码 → 提示文案映射表；`RATE_LIMITED` 读取 `Retry-After` 退避；`IDEMPOTENCY_CONFLICT` 提示"请求已变更，请重试" |
| 会话 | access token 仅内存；refresh token 存安全存储；登出即清 |
| 分页/列表 | 统一 `{items,total,page,pageSize}` 处理与空态 |
| 幂等 | 退款等动钱操作在前端生成并保存 `Idempotency-Key`，重试必复用 |
| 隐私 | 儿童数据、证件 URL 不写入日志/埋点/全局缓存；证件 URL 用后即弃 |
| UX 状态 | 每页必含 loading / empty / error / retry / permission denied（`specs/11` §UX requirements） |
| 环境 | 仅指向 API base URL 一个配置项；**禁止任何密钥/证书/商户号进入前端**（构建期注入的也必须是公开值） |

## 4. 分阶段计划

| 阶段 | 目标 | 产出 | 依赖 |
|---|---|---|---|
| **F0 基建** | API client、会话、错误映射、类型复用、环境配置 | 两端共享的 client 包/模块与最小骨架页 | 无 |
| **F1 管理台 MVP** | 运营可不用直连 DB：登录 → Dashboard → 商家审核 → 订单 → 审核 → 平台配置 | 12 个可用页面 | **G1 决策**（临时可用 `bootstrap` + mock 登录在本地推进 UI） |
| **F2 小程序家长主链路** | 浏览 → 预约 → 支付 → 订单 → 评价（E2E-01 对应） | 家长端 15 页 | F0；真实支付需微信商户号（可先用 mock） |
| **F3 小程序导师端** | 入驻 → 验证 → 服务/时段 → 接单交付 | 导师端 12 页 | F0；**G3**（上传链路本地不可用，需后端补路由或用替代方案） |
| **F4 消息与举报** | 会话列表/详情、屏蔽、举报与申诉 | 聊天与举报页 | **G4**（IM 供应商/后端发消息能力） |
| **F5 职业赛道** | 开关打开后复用链路 | 5 页 | F2/F3；开关 `career_marketplace_enabled` |
| **F6 补齐与打磨** | 时间线、通知、收入（如后端补齐）、离线与埋点 | 增量页面 | 后端补齐 G5–G15 的对应项 |

## 5. 风险与控制

| 风险 | 控制 |
|---|---|
| 用微信 mock 登录充当管理台登录 | 明确标注为本地-only；生产前必须落地 G1 |
| 前端自行计算金额/状态 | 代码评审清单项；金额与状态一律来自服务端响应 |
| 儿童数据泄漏到日志/埋点 | 隐私清单：禁止在埋点、日志、全局 store 中出现 child 字段 |
| 证件 URL 被缓存/外泄 | 5 分钟签名 URL，用后即弃，不落盘 |
| 绕过业务校验做"体验优化" | 任何校验放宽必须回到 spec 与后端，前端不得本地放行 |
| 退款重复提交 | 前端 `Idempotency-Key` 持久化到操作意图，重试复用 |
| 429 造成雪崩 | 统一退避 + 关键操作禁用重复点击 |

## 6. 验收口径（前端任务通用）

1. 页面使用的接口全部可在 `api-contract-map.md` 中追溯；
2. 覆盖 `specs/11` §UX requirements 的六种状态；
3. 金额页展示服务、时长、单价、总价、订单号与退款规则入口；
4. 每个写操作都能解释它对后端状态机的影响；
5. 单元测试覆盖 client 的解包、401 重放、错误码映射；
6. E2E 至少覆盖家长主链路（对齐 E2E-01）与管理台一次完整审核处置。
